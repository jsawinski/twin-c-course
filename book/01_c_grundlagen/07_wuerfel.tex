\section{Programm: Ein Würfel}
\label{sec:c:wuerfel}

Ein Würfel liefert ja bekanntlich zufällige Zahlen von 1 bis 6. Um so etwas zu programmieren, brauchen wir Zufallszahlen -- und die kann der Computer auf Befehl liefern:
\begin{code}[numbers=none]
#include <stdlib.h>

int rand();
\end{code}
Der Befehl \codeinline{rand()}, definiert in der Kopfdatei ``stdlib.h'' (\emph{standard library}, so viel wie ``Standardbibliothek''), gibt Euch Zufallszahlen vom Typ \codeinline{int}. 

\begin{exercise}
    Schreibt ein Programm, das eine Zufallszahl auf dem Bildschirm ausgibt. Ihr könnt dazu einfach Euer Programm aus Abschnitt~\ref{sec:c:zahlen} kopieren und die 42 durch \texttt{rand()} ersetzen. Vergesst aber nicht, die Kopfdatei \texttt{stdlib.h} einzubinden. Was fällt Euch auf, wenn Ihr das Programm mehrmals aufruft? Probiert auch aus, 5 Zufallszahlen mit einer Schleife auszugeben.
    \begin{solution}
        Das Programm, um 5 Zufallszahlen auszugeben, sieht zum Beispiel folgendermaßen aus:
\begin{code}[numbers=none]
#include <stdio.h>
#include <stdlib.h>

int main() {
    for(int i = 1; i <= 5; i++) {
        int zahl = rand();
        printf("Zufallszahl %d: %d\n", i, zahl); 
    }

    return 0;
}
\end{code}
Auf dem Computer des Autors ist die Ausgabe folgende:
\begin{verbatim}
Zufallszahl 1: 1804289383
Zufallszahl 2: 846930886
Zufallszahl 3: 1681692777
Zufallszahl 4: 1714636915
Zufallszahl 5: 1957747793
\end{verbatim}
    Möglicherweise seht Ihr genau die gleiche Reihenfolge, das kann aber von Betriebssystem und Compiler abhängen.
    (Ihr könnt nun im Text nach der Aufgabe im Kapitel~\ref{sec:c:wuerfel} weiter machen, dort findet Ihr die Erklärung für dieses Verhalten.)
    \end{solution}
\end{exercise}

In der Aufgabe habt Ihr gesehen, dass die generierten Zufallszahlen immer mit derselben Zahl anfangen und darüber hinaus auch die gleiche Reihenfolge aufweisen. Das liegt daran, dass \emph{echte} Zufallszahlen sehr schwer herzustellen sind.\footnote{%
    Selbst viele moderne Computer haben keine echten Zufallszahlengeneratoren. Die Betriebssysteme helfen sich jedoch damit, Zufallszahlen aus dem Benutzerverhalten (z.B. durch Tastatureingabe) zu generieren.}
Daher wurden mathematische Algorithmen entwickelt um eine Zahlenfolge zu berechnen, die sich so verhält, als wäre sie zufällig. Dabei ist es möglich, den Anfangswert festzulegen (der sogenannte \emph{seed}, englisch für ``Saatkorn'' -- gemeint ist der Startwert der Zahlenfolge). Um nun beim Programmstart einen neuen Anfangswert zu setzen, behilft man sich im Allgemeinen damit, die aktuelle Zeit zu nehmen. Dazu schreibt man sich die Funktion:
\begin{code}[numbers=none]
#include <stdlib.h>
#include <time.h>

void random_init() {
    srand(time(NULL));
}
\end{code}
Hier ist \codeinline{srand(seed)} die Funktion, mit der man den Anfangswert der Zufallszahlenfolge setzt und \codeinline{time(NULL)} die Anzahl der Sekunden seit dem 1.1.1970 (dafür benötigen wir die Kopfdatei \texttt{time.h}, siehe auch Funktionsreferenze S.~\manrefpage{time}).

Wenn wir einen Würfel programmieren wollen, der z.B. die Zahlen 1 bis 6 liefert, dann müssen wir noch einen geeigneten Weg finden, das Ergebnis von \codeinline{rand()} auf diesen Bereich einzuschränken. Wir verwenden hier die Operation \textbf{modulo}, in C/C++ wird dafür der Operator \texttt{\%} benutzt.\footnote{%
    Das ``modulo'' ist der Rest einer Division, Beispiel: 10 ÷ 3 = 3 Rest 1.}
Die Funktion \codeinline{rand()} liefert nun die Zahlen 0 bis \texttt{RAND\_MAX} (siehe Lösung der obigen Aufgabe; Funktionsreferenz S.~\manrefpage{rand}). Ihr könnt nun einmal ausprobieren, was passiert, wenn Ihr in Eurem Programm die Zeile
\begin{code}[numbers=none]
    int zahl = rand();
\end{code} 
durch
\begin{code}[numbers=none]
    int zahl = rand() % 6;
\end{code} 
ersetzt. Wenn Ihr das nun ausprobiert, merkt Ihr, dass die Zahlen von 0 bis 5 ausgegeben werden -- das heißt, wir müssen noch 1 dazu addieren, um die Zahlen von 1 bis 6 zu erhalten. 

Da wir solche Zufallszahlen aber noch in anderen Programmen nutzen wollen, ist es ratsam, eine Funktion zu schreiben, bei der man festlegen kann, was der kleinste und was der größte Wert ist. 

\paragraph{\textbf{Einschub}: Funktionen} %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Im ersten Programm (``Hallo Welt!'', S.~\ref{sec:c:hallo-welt}) habt ihr zwei Funktionen kennengelernt. Zum einen das \texttt{int main()} und zum anderen das \texttt{printf}. Der Unterschied ist, \texttt{main} habt Ihr selbst geschrieben, \texttt{printf} dagegen war hinter einer Kopfdatei (genauer: \texttt{stdio.h}) ``versteckt''. Wir haben auch schon im letzten Kapitel weitere eigene Funktionen eingeführt: \codeinline{konsole_start()} und \codeinline{tropfen()}. Der Aufbau ist in allen Fällen der gleiche:
\begin{verbatim}
Rückgabetyp Funktionsname ( Parameter ) {
    Funktionskörper
}
\end{verbatim}
Der \emph{Rückgabetyp} kann jeder Datentyp sein, den C kennt -- zum Beispiel \texttt{int} oder \texttt{double}. Wenn man eine Funktion programmieren will, die nichts zurück gibt (wie oben das \codeinline{random_init()}), dann verwendet man \texttt{void} (deutsch: ``Leere'' oder ``Nichts'').

Den \emph{Funktionsnamen} könnt Ihr selbst wählen. Es gibt aber eine ganze Reihe von Regeln, die man beachten muss. Für den Anfang solltet Ihr Euch einfach an folgende Regel halten: verwendet einen Funktionsnamen der aus ganzen Wörtern besteht (kleingeschrieben) und durch Unterstriche verbunden ist, zum Beispiel: \codeinline{diese_funktion_macht_etwas()}.\footnote{%
    In der Informatik, so wie auch in der Wissenschaft und vielen anderen Bereichen, hat sich die englische Sprache durchgesetzt. Wenn Ihr bereits Englisch lernt und wisst, wie die Funktion auf Englisch geschrieben werden könnte, dann verwendet Englisch. Im genannten Beispiel wäre das \codeinline{this_function_does_something()}.
}

Die \emph{Parameter} sind die ``Eingangswerte'' der Funktion. In der Funktion verhalten sie sich wie normale Variablen. Sie werden als Liste übergeben -- in C getrennt durch Kommas. Jeder Parameter besteht aus einem Datentyp und einem Variablennamen, so wie Ihr es schon von der Deklaration von Variablen kennt. Erinnert Ihr Euch an \codeinline{tropfen(int b)} aus dem letzten Kapitel? Jetzt versteht Ihr, was da passiert ist: \texttt{b} war der Parameter, \texttt{void} der Rückgabetyp (weil die Funktion nichts zurückgibt), und der Code in den geschweiften Klammern war der Funktionskörper.

Wenn man einen Wert zurückgeben will, benutzt man \codeinline{return}. Ein Beispiel:
\begin{code}[numbers=none]
int erhoehe(int n) {
    return n+1;
}
\end{code}
Diese Funktion gibt den Wert \codeinline{n+1} zurück. Wichtig ist: mit dem \texttt{return} kehrt die Funktion zurück, sie ist zu Ende -- jeglicher Code nach \texttt{return} wird nicht mehr ausgeführt.

\noindent
Damit können wir nun wieder zu den Zufallszahlen zurückkehren. Für den Würfel und folgende Programme brauchen wir eine Funktion, die Zufallszahlen zwischen zwei Werten liefert. Die beiden Werte nennen wir \texttt{min} (für ``Minimum'', das heißt die kleinste Zahl) und \texttt{max} (für ``Maximum'', das heißt die größte Zahl). Zunächst fangen wir mit dem obigen Beispiel an:
\begin{code}[numbers=none]
int zahl = rand() % max;
\end{code}
Wie Ihr festgestellt habt, liefert das \emph{modulo} als Ergebnis eine Zufallszahl zwischen \texttt{0} und \texttt{max-1}. Für einen normalen Würfel (einer der mit 1 beginnt und bei, zum Beispiel 20 endet) müssten wir also noch eine \texttt{1} addieren. Was passiert nun aber mit dem \texttt{min}?
\begin{exercise}
    \begin{enumerate}[label=\alph*)]
    \item 
        Die Berechnung hängt eng mit dem ``Zaunpfahlproblem'' zusammen: wenn ihr einen Zaun bauen wollt, der alle Meter einen Zaunpfahl haben soll, wie viele Zaunpfähle braucht man dann für \qty{10}{\meter} Zaun?
    
    \item 
        Ein Architekt sagt Euch, der Zaun beginnt \qty{6}{\meter} neben dem Haus und endet in einer Entfernung von \qty{10}{\meter} vom Haus. Wie lange ist der Zaun und wie viele Zaunpfähle braucht Ihr?

    \item 
        Wenn Ihr die vorhergehenden Teilaufgaben gelöst habt, dann könnt Ihr sicher auch beantworten, warum das folgende Beispiel falsch ist, wenn Ihr alle Zahlen von \texttt{min} bis \texttt{max} haben wollt:
\begin{code}[numbers=none]
int random_number(int min, int max) {
    return min + rand() % max;
}
\end{code}
        Findet heraus, wie die Funktion richtig geschrieben werden muss.
    \end{enumerate}

    \begin{solution}
        \begin{enumerate}[label=\alph*)]
        \item 11
        \item \qty{4}{\meter}, 5 Zaunpfähle
        \item 
            Wie beim vorhergehenden Zaunpfahlproblem ist \texttt{max-min} die Distanz zwischen \texttt{min} und \texttt{max}. Die Anzahl der Zahlen ist aber \texttt{max-min+1}. Wenn ihr also \texttt{rand() \% (max-min+1)} berechnet, braucht man nur noch \texttt{min} dazuzuaddieren:
\begin{code}[numbers=none]
int random_number(int min, int max) {
    return min + rand() % (max-min+1);
}
\end{code}
        \end{enumerate}
    \end{solution}
\end{exercise}
